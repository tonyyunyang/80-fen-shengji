# 本项目的上海八十分规则

[English](rules.md) · [玩家指南](guide.md)

实现的规则档案为 `shanghai-80fen-0.7.14-v1`，以 [ChannonTian/80fen 的固定版本](https://github.com/ChannonTian/80fen/blob/96f69258b68495904f360a199738b161da4f4998/docs/RULES.md)为参考。各地、各桌可能存在差异；这里描述本项目实际执行的规则。

## 牌、队伍与分数

四席分别为南 0、东 1、北 2、西 3；南北一队，东西一队。两副牌共 108 张，每人 25 张，另有八张底牌。5 计 5 分，10 与 K 各计 10 分，整副牌共有 200 分。

同牌面在两副牌中有不同物理 ID。引擎检查所有牌的身份、花色与点数，保证不重不漏；不能把一张牌重复使用，也不能给某个 ID 伪造牌面。

## 发牌、亮主与庄家

新开的浏览器对局随机选择首局庄家，所以任意一队都可能先攻。已知庄家时，亮主与反主改变主花色，不改变庄家。

单人／观战桌默认使用[持续发牌](continuous-dealing.md)：100 张牌按席顺序发出，默认每张 500ms，也可选择 700ms。只能使用已收到的牌亮主。一张级牌可亮对应花色；同花色同点数的级牌对子更强；小王对与大王对可亮无主，大王对最强。

更强的声明可以反其他席的主。不能自行反到别的花色；当前亮主者可以把单张加强为同花色级牌对子，前提是尚未被王对反主。

多个请求按收到时的合法性处理：后到的同强度声明被私下丢弃，不自动升级为对子、不换牌，也不延长时间。模型既要在收到的观察中有资格亮该牌，也要在回应到达时仍然合法。

发完第 100 张牌后，所有人共享至少五秒的收尾时间。被接受的亮主会重新开始完整的五秒窗口；思考、过牌、失败或无效声明不会延长它。收尾期间不继续发牌。

多人共用一台设备使用顺序发牌与交接模式，避免看到其他人的手牌。旧存档与规则测试也可以显式使用顺序模式。

无人亮主时为无主。若该局未预定庄家，最终亮主者坐庄；无人亮主则由首抓者坐庄。庄家拿底后从 33 张中扣回恰好八张，扣底没有花色、主牌或分数限制。

可选的重新发牌默认关闭。开启后，攻庄方若总分不超过 15，或主牌不超过三张，可按规则请求；一局最多重新发三次。设置可选择保留已知庄家，或重新争庄。重新争庄时双方按各自当前级数亮主。

## 主牌与大小

所有王、所有级牌和主花色的牌，都归到有效主花色 T。大小为：

**大王 > 小王 > 主花色级牌 > 其他花色级牌 > 普通主花色牌。**

无主时，所有级牌同大，位于小王之下。普通花色的大小跳过当前级牌。相同大小先出的牌大。

对子必须同花色、同点数。拖拉机由同一有效花色、大小连续的对子组成。例如打 7 时，红桃 66 与 88 相邻；打 2 时不相邻。其他花色级牌的同大小对子按独立层处理，不会因为多一副同大小对子而拆散原本连续的拖拉机。

## 跟牌

跟牌张数必须与首攻相同。尽可能跟足首攻的有效花色；若有对子，要满足相应的对子义务。拖拉机首攻还要求：有同长度拖拉机就跟；开启部分拖拉机跟牌时，不够长也应跟最长的可用短拖拉机。严格跟拖与部分跟拖默认开启，部分跟拖可在开桌前关闭。

只有结构与首攻匹配的出牌才能争大。同结构主牌可以将吃副牌；同一有效花色中按顶张大小比较，同大归先出者。

## 甩牌

可以把同一有效花色的多个分量一起甩出。若任意其他人——包括搭档——在该花色中能压住某一分量，甩牌会被裁定只出顶张最小的分量，不额外罚分。

混合有效花色的首攻不合法。非法请求在修改牌局前被拒绝；它与引擎裁定失败的甩牌不同。

## 抠底、升级与下一局

攻方最终至少拿到 80 分即可上台。如果攻方赢最后一墩，将底牌分乘以 **末墩首攻张数的两倍** 后加入攻方总分。

| 攻方最终分数 | 结果 |
| --- | --- |
| 0 | 庄方升三级 |
| 5–35 | 庄方升两级 |
| 40–75 | 庄方升一级 |
| 80–115 | 攻方上台，不升级 |
| 120 及以上 | 攻方上台，每超过 80 分四十分升一级 |

庄方赢时，下局由其搭档坐庄；攻方上台时，由原庄家的下一席坐庄。默认必打级为 2、5、10、K：升级越过必打级时停在该级，只有成功守住当前必打级才能通过。打过 A 赢得整场。

速通模式使用 2 → 5 → 10 → K → A，每次正升级最多前进一步，关闭必打级检查。80–115 分的上台仍然不升级，因此不保证固定局数结束。

一局在手牌出完时结束，不一定是 25 墩。对子、拖拉机与甩牌都会改变实际墩数。

## 验证

`test/engine.test.js` 包含牌身份守恒、跟牌、拖拉机、甩牌、计分与必打级的例子，以及与保留参考逻辑的对照。若规则有争议，请在 Issue 或 PR 中给出明确牌例，而不是把某地习惯默认为所有牌桌的规则。
